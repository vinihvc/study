# Study — Agent Guide

Interactive study site for algorithms and data structures. Users read MDX problem write-ups, edit JavaScript in the browser, and run code in a Web Worker after esbuild transpilation.

**Live:** [study.vini.one](https://study.vini.one) · **Repo:** [github.com/vinihvc/study](https://github.com/vinihvc/study)

## Commands

| Task                   | Command           |
| ---------------------- | ----------------- |
| Dev server (port 3000) | `pnpm dev`        |
| Production build       | `pnpm build`      |
| Preview build          | `pnpm preview`    |
| Lint / format check    | `pnpm lint:check` |
| Auto-fix lint & format | `pnpm lint:fix`   |

Package manager is **pnpm**. Node runs the Nitro output via `pnpm start` after build.

## Tech stack

- **Framework:** [TanStack Start](https://tanstack.com/start) (React 19, file-based routes, SSR shell)
- **Bundler / dev:** Vite 8 + `@vitejs/plugin-react`
- **Deploy runtime:** Nitro (`nitro` 3.x, Vercel preset)
- **Routing:** TanStack Router (`src/routes/`, `routeTree.gen.ts` is generated)
- **Content:** [Fumadocs MDX](https://fumadocs.dev/docs/mdx) (headless) — exercises as MDX in `src/content/exercises/`
- **Styling:** Tailwind CSS v4 (`@tailwindcss/vite`), `tailwind-variants`, prose styles in `src/styles/`
- **UI primitives:** Ark UI (`@ark-ui/react`) — combobox, dialog, menu, popover, etc. in `src/components/ui/`
- **Editor:** CodeMirror 6 (`@uiw/react-codemirror`, GitHub dark theme)
- **In-browser JS:** `esbuild-wasm` (transpile) + dedicated worker (`src/lib/code-runner.worker.ts`)
- **Validation:** Zod 4
- **Lint / format:** Ultracite 7 (Oxlint + Oxfmt) — configs: `oxlint.config.ts`, `oxfmt.config.ts`

## Project layout

```
src/
  routes/           # TanStack file routes
    index.tsx       # Home — exercise grid sorted by difficulty
    e/$slug.tsx     # Exercise detail (MDX + editor + nav)
    __root.tsx      # HTML shell, header, footer, global SEO
  content/exercises/  # MDX exercise sources (not hand-edited generated output)
  components/
    blocks/         # Code editor, spoilers, exercise examples
    layout/         # Header (incl. command search), footer
    ui/             # Reusable Ark-based UI
    knowledge/      # Big-O reference block
  lib/              # exercises source, run-code, transpile, worker, utils
  types/            # exercise test schema, difficulty map
  config/site.ts    # Site name, URL, OG metadata
source.config.ts    # Fumadocs MDX collection schema + rehype plugins
```

Path aliases: `@/*` → `src/*`; `collections/*` → `.source/*` (generated by `fumadocs-mdx/vite`).

## Routing

| Route      | Purpose                                                                        |
| ---------- | ------------------------------------------------------------------------------ |
| `/`        | Lists all exercises (easy → medium → hard)                                     |
| `/e/$slug` | Single exercise; slug derived from title (`"Valid Anagram"` → `valid-anagram`) |

`prev` / `next` navigation is computed in `src/lib/exercises.ts` from collection document order.

## Exercises (content model)

Each exercise is an MDX file under `src/content/exercises/` with frontmatter validated by `source.config.ts`:

| Field         | Required | Notes                            |
| ------------- | -------- | -------------------------------- |
| `title`       | yes      | Drives slug and SEO              |
| `difficulty`  | yes      | `easy` \| `medium` \| `hard`     |
| `starter`     | yes      | Default editor code (YAML block) |
| `description` | no       | Subtitle on exercise page        |
| `excerpt`     | no       | Card preview                     |
| `solved`      | no       | Metadata flag                    |
| `tests`       | no       | Example I/O blocks (see below)   |

**MDX body:** Problem statement and optional `<Spoiler>` hints. Custom MDX components are wired in `src/components/content-block.tsx`: `Spoiler`, `BigO`, styled `pre` (Shiki via rehype in `source.config.ts`). Exercise MDX is loaded client-side via `collections/browser` on `/e/$slug`.

**Adding an exercise:** Create `src/content/exercises/<name>.mdx`, match the schema, restart dev if the collection does not hot-reload. Slug is `title.toLowerCase().replace(/ /g, "-")`.

### Test cases (frontmatter)

Defined in `src/types/exercise.ts` (`testCaseSchema`). Used for **display only** in `ExerciseExamples` — not auto-graded yet.

```yaml
tests:
  - name: Input 1
    code: isAnagram("anagram", "nagaram")
    expectedInput: { s: "anagram", t: "nagaram" }
    expectedResult: true
    compare: exact # optional: exact | unordered
```

## Code execution flow

1. User edits code in `CodeBlocks` / `CodeBlocksDrawer` (persisted in `localStorage` key `exercise-code:{slug}`).
2. **Run** (`Mod+Shift+Enter`): `runExerciseCode` → `prepareExerciseCode` (esbuild-wasm, ES2020) → worker.
3. Worker wraps user code in an async IIFE, injects a capturing `console`, enforces **5s timeout**.
4. Output: `{ ok: true, logs: string[] }` or `{ ok: false, error: string }`.

User code is plain **JavaScript** (not TypeScript in the editor). Keep starters as runnable snippets with `console.log` for manual verification.

## UI conventions

- Prefer existing components in `src/components/ui/` (Button, Badge, Dialog, Command palette, etc.).
- Use `cn()` from `@/lib/utils` for class merging (`clsx` + `tailwind-merge`).
- Difficulty styling: `DIFFICULTY_MAP` in `src/types/difficulty.ts`.
- Responsive pattern: desktop sticky sidebar editor (`CodeBlocks`); mobile drawer (`CodeBlocksDrawer`).
- Icons: `@remixicon/react` and `lucide-react` (both in use).
- Site copy and URLs: `SITE_CONFIG` in `src/config/site.ts`.

## What to avoid

- Do not edit `src/routeTree.gen.ts` or `.source/` by hand.
- Do not add framework-specific guidance for Next.js — this is TanStack Start + Vite.
- Do not expand scope when fixing bugs (see Karpathy guidelines in `.cursor/rules/karpathy-guidelines.mdc`).
- Avoid barrel files that re-export entire trees unless the codebase already uses that pattern nearby.

## Code quality (Ultracite)

This repo enforces style via **Ultracite** (Oxlint + Oxfmt). Run `pnpm lint:fix` before committing.

**Quick reference**

- `pnpm lint:check` — lint/format without writes
- `pnpm lint:fix` — auto-fix

Extends: `ultracite/oxlint/core`, `react`, `tanstack`.

**Principles agents should follow**

- Strict TypeScript; prefer narrowing over assertions; no `any` unless unavoidable.
- Function components and hooks rules; semantic HTML and accessible controls.
- Early returns, focused functions, meaningful names.
- Remove `console.log` / `debugger` from production paths (editor/run output is intentional).
- Match existing patterns in the file you touch.

Detailed Ultracite/React/TanStack rules are enforced by the linter; rely on `pnpm lint:fix` rather than duplicating the full rule list here.

## Verification

After substantive changes:

1. `pnpm lint:check` (or `pnpm lint:fix` then `pnpm lint:check`)
2. `pnpm build` — includes `tsc --noEmit`
3. Manually smoke-test: home list, open an exercise, run starter code, prev/next links, command palette search (`Header`).
